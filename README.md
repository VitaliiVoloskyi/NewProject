# Spry — Meetings App

List, create, and delete meetings with participants. FastAPI + PostgreSQL backend, React + shadcn/ui frontend, all run with Docker Compose. See [SPEC.md](SPEC.md) for the full specification.

## Quick start

Requires Docker.

```sh
make up      # creates .env from .env.example, builds and starts everything
make seed    # optional: sample participants and meetings
```

- App: http://localhost:3000
- API docs: http://localhost:8000/api/docs

If port 5432 is already in use on your machine, set `DB_PORT` in `.env` (e.g. `DB_PORT=5433`).

## Common commands

Run `make` to list all targets. The most used:

| Command | What it does |
|---|---|
| `make up` / `make down` | Start / stop the stack |
| `make logs s=backend` | Follow logs of one service |
| `make test` | Backend tests (starts Postgres in Docker, runs pytest via uv against `<db>_test`) |
| `make lint` / `make format` | Ruff + oxlint/Prettier |
| `make migration m="..."` | Autogenerate an Alembic migration |
| `make psql` | Open a psql shell |
| `make clean` | Stop and delete the database volume |

## Local development without rebuilding images

Requires [uv](https://docs.astral.sh/uv/) and Node.js.

```sh
make install        # uv sync + npm install
make dev-backend    # Postgres in Docker, API on :8000 with reload
make dev-frontend   # Vite on :5173, proxies /api to :8000
```

## Deploy to AWS

Step-by-step guide (including Google sign-in): [docs/DEPLOY.md](docs/DEPLOY.md). Everything is in [`infra/`](infra/), on two roads:

- **Infrastructure as Terraform** (`infra/*.tf`): Cognito, the weekly report and the agenda parser.
  State and runs live in **HCP Terraform** (workspace `spry-dev`): a pull request gets a plan as a
  check, a merge to `main` applies it. Nobody applies from a laptop. Why: [ADR 0007](docs/adr/0007-terraform.md).
- **Application code and the older stacks** (network, API, database, site: `infra/*.yaml`, still
  CloudFormation): GitHub Actions runs `make deploy-backend` and `make deploy-frontend` on every push to `main`.

```
https://xxxx.cloudfront.net  ->  CloudFront  ->  private S3 bucket (React app)
                             ->  Lambda function URL (FastAPI container)  ->  RDS PostgreSQL (db.t4g.micro)
                             ->  Cognito (email + Google)
GitHub push to main  ->  lint + tests  ->  OIDC role  ->  make deploy-backend && make deploy-frontend
GitHub merge to main ->  HCP Terraform  ->  plan + apply of infra/*.tf (dynamic AWS credentials)
```

| Command | What it does |
|---|---|
| `make infra-plan` | Speculative plan of `infra/*.tf` in HCP Terraform: Cognito (`auth.tf`), weekly report ([docs/REPORTS.md](docs/REPORTS.md), `reports.tf`), Paste an agenda + $5 budget ([docs/AGENDA-PARSER.md](docs/AGENDA-PARSER.md), `ai.tf`). Changes nothing |
| `make infra-output` / `make auth-env` | Show Terraform's outputs / write the Cognito ids and the parser URL to `.env` |
| `make deploy-backend` | Build the image, push to ECR tagged with the commit SHA, deploy Lambda + RDS, then ship the same code to the report builder and the parser (`make deploy-functions`) |
| `make deploy-frontend` | Build the bundle, sync to S3, invalidate CloudFront |
| `make report-now WEEK=2026-W39` | Build and email one week's report on demand |
| `make verify-recipients` | Send SES verification links to `REPORTS_RECIPIENTS` (SES sandbox) |
| `make parse TEXT="..."` / `make parse-eval` | Parse one text, or the five test inputs, from your laptop |
| `make deploy-ci` | IAM role GitHub Actions assumes via OIDC (once) |
| `make add-domain` | Optional custom domain for the frontend |
| `make destroy` | Delete frontend and backend (destroy the Terraform resources in HCP Terraform first) |

There is no `terraform apply` target: infrastructure changes are pull requests, applied by HCP Terraform after the merge. To change a setting of Cognito, the report or the parser (schedule, model, allowed origins, ...), edit `infra/terraform.tfvars` or the `.tf` files, open a pull request and read the plan in its check. Secrets (the Google client secret) and personal addresses (report recipients, budget email) are variables of the HCP Terraform workspace, not files.

No AWS keys live in `.env`, in GitHub or in HCP Terraform: locally the scripts use your `aws configure` profile, CI uses short-lived OIDC credentials, and HCP Terraform runs assume a role through OIDC too ([`infra/bootstrap`](infra/bootstrap/main.tf)). The commands are bash scripts: run them in Ubuntu, WSL or macOS, not in PowerShell.

## Layout

```
backend/    FastAPI app (app/), Alembic migrations (alembic/), tests (tests/)
frontend/   Vite + React + shadcn/ui (src/components/ui is generated by shadcn)
infra/      Terraform (*.tf, HCP Terraform workspace spry-dev), the older CloudFormation
            templates (*.yaml) and the deploy scripts; infra/bootstrap: HCP Terraform's AWS role
docs/       Deployment guide, architecture decision records (docs/adr)
.github/    CI (lint, tests) and CD (deploy on push to main)
```
